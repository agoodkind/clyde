# Embedded conversation search

Clyde searches conversations through `goodkind.io/lm-semantic-search/library`. Clyde loads provider artifacts, selects content, and prepares search eligibility. The library embeds distinct content once, stores immutable occurrences in a SQLite WAL catalog, and ranks occurrences using generic typed metadata. Clyde creates and owns the Milvus SDK client for its Milvus profile and injects the library's Milvus vector adapter. The library's embedded vector adapter retains an offline code search profile. Clyde does not call an LMS daemon. The library does not interpret conversations or provider artifacts.

This proposed design supersedes the backend selection, deletion, and fixed depth search behavior in the earlier local conversation search specification. The existing CLI and MCP search operations remain the public entry points.

## Select content and retain occurrences

Clyde's registered provider parsers discover artifacts and read transcript messages. `BuildSemanticConversationDocuments` selects fields for indexing. Clyde converts each selected nonempty field into an occurrence. The namespace identifies Clyde's corpus. The owner ID is the stable conversation ID. The row key includes the original message index, content kind, tool index when applicable, part suffix, and projection profile identity. Routine batch generation does not change the row key. Provider parsers append messages without renumbering earlier ones, and an earlier message keeps its index and text after an append. A Cursor agent transcript can also extend its trailing message in place when the artifact grows. For such an artifact, Clyde withholds the trailing message until a later message exists or the artifact has stayed unchanged for 30 minutes, whichever comes first. Normal synchronization uses append mode and never deletes an occurrence after a policy change, truncated artifact, or source loss.

The library keys a vector by the exact embedding input bytes after its declared input transformation, model identity, and dimension. Multiple occurrences reference the same vector. Clyde tracks complete selected fields in its own projection state. The library receives stable part row keys and publishes all staged parts after a verified complete batch. Normal passes repeat existing IDs without inserting occurrences. Appended messages add only their new rows. An explicit projection profile change creates new row identities while retaining earlier occurrences. Metadata changes update scalar visibility without rewriting vectors.

The explicit `projection_profile` selects immutable source identity rules. New ingestion requires `p3` and stores original selected source text, raw field digests, and immutable prepared byte spans. Lexical and embedding preparation replace NUL bytes with spaces without changing source offsets. Search-only configuration can select `p1` or `p2`, preserves their existing namespace declarations and stored excerpts, and returns unavailable context without source identity. An omitted profile never activates a new projection against an existing store. Selecting a profile does not authorize a schema migration, production reset, or re-embedding.

The default selects chat text and tool calls. It excludes tool output, thinking, archived conversations, and subagent conversations. Provider, role, chat, tool call, tool output, thinking, archive, and subagent settings remain typed configurable levers. Clyde offers only selected nonempty content. A tool-only message remains eligible when tools are selected. Selected thinking-only content remains eligible when chat text is empty. A message without selected content produces no occurrence. Config changes add a policy version and selected occurrences without removing earlier data.

Clyde updates stored metadata for an indexed owner when archive, workspace, provider, or subagent classification changes, even when the current ingestion policy excludes that owner. It calls `ReprojectScalars` with exact stable row keys, mutable declared scalar values, a monotonic projection order, and an idempotency token. The library commits the effective metadata projection atomically with zero vector writes. Clyde does not load excluded transcript fields for that update. A missing artifact retains its last accepted metadata.

Clyde uses each provider's display text and display language hint to prepare tool search text. A bash display uses `gksyntax/shelldecomp` to extract program names and read and write targets. An opaque command uses the raw display. Trimmed duplicate tokens appear once. The tool name starts every prepared part, including parts after the first model-sized split. The parser preserves valid UTF-8 text and does not infer tool type from harness labels or JSON shape. Each occurrence stores the original message index and `loadRules` tag. Clyde never loads excluded thinking or output solely to create context for an earlier hit.

## Search through generic filters

Clyde registers a namespace with declared typed scalar columns. Clyde selects each logical row and calls the library's `PrepareText` helper. The helper returns ordered model-sized parts, stable part suffixes, source spans, and exact transformed embedding input without truncating selected text. Clyde assigns part identity and scalar metadata to those prepared parts. The library's append operation does not split them again. An append batch includes namespace, owner ID, stable part row key, sort key, selected source text, embedding input, and typed scalars. Clyde keeps whole-field identity in its own projection state. Clyde supplies conversation ID, provider, workspace, role, timestamp, archive and subagent state, message index, `loadRules`, and projection profile as scalar values. The library validates declared types and evaluates typed equality, membership, range, prefix, null, presence, and Boolean filters. Clyde sends no raw Milvus expression.

Clyde translates provider, workspace, explicit conversation, archive, subagent, role, time, and selected projection profile into generic typed predicates before the query. Workspace matching uses a prefix predicate. An explicit conversation set uses membership. The library reads occurrence metadata and evaluates those predicates in one query snapshot. Missing raw artifacts never erase stored eligibility. Clyde passes a score floor, per conversation group cap, and page request. The library applies eligibility predicates before scoring. It applies the score floor and conversation quota after global ranking and before paging. Clyde does not discard ranked hits or repeat the search with a larger limit.

The library returns stable occurrence IDs, scores, selected text, scalar snapshots, an exact continuation cursor, and an exact `hasMore` state. The same query and snapshot produce the same order. A smaller page is a prefix of a larger page within that snapshot. Equal scores use a stable occurrence key. A page is short only when fewer eligible hits remain. Errors return typed failures and no partial page. Clyde maps hits into the existing CLI and MCP fields. Clyde can satisfy an offset request by consuming exact cursor pages inside one snapshot. A later independent offset request opens another snapshot and can see newly committed rows. Clients use the continuation cursor for stable pagination across requests.

The excerpt and record metadata come from the stored occurrence. Clyde records the matched message identity and selected content digest at ingestion. A context read uses the recorded `loadRules`, verifies the source stamp before and after the read, and compares every selected field in the relevant context slice with committed identities and raw content digests. A removed committed field, uncommitted neighbor, or changed selected text makes context unavailable. A later append to the transcript does not invalidate an unchanged earlier message. A missing or incompatible source returns the stored excerpt with unavailable context. Clyde never renders incompatible transcript text as context for a hit. A source absent from a later raw scan remains stored and eligible under its last accepted metadata and policy.

## Commit and recover ingestion

Clyde records an outbox batch before calling the library. It stages every new prepared part for one owner generation, then sends `GenerationSeal` with the expected row count and manifest hash at the end. `CommitGeneration` verifies the staged manifest and atomically publishes those new rows. The library returns a receipt with the committed generation. Clyde marks the batch delivered only after it confirms that receipt. A replay of the same batch is idempotent. An interrupted read, embed, transaction, or restart preserves the prior searchable rows. Clyde reports pending work through freshness and retries it. The batch identifier, source identity, projection profile, new occurrence IDs, seal, and committed generation make recovery explicit. A metadata-only update uses `ReprojectScalars` and performs no vector write.

Clyde opens the library inside its daemon lifecycle after creating its Milvus client and vector adapter. The daemon stops ingestion workers before closing the library, adapter, and client during reload or shutdown. The library does not close the caller owned Milvus client. Failed open, embed, store read, and Milvus query operations produce typed errors rather than an empty successful page. Search-only mode reads committed data without ingestion. Ingestion-only mode updates data without serving search. Neither mode needs an LMS process or socket.

The library packages pinned CGO and native dependencies for supported macOS and Linux builds. Clyde imports `gksyntax` to decompose shell commands. Its native grammar currently requires a reproducible pinned source checkout in the build and release workspace because the module archive does not include it. Clyde pins an exact library commit and adds no machine-specific replacement. Model identity, resolved revision, normalization, dimension, SQLite path, Milvus target, batch size, and search resource controls use explicit configuration. The immutable store descriptor binds model, revision, dimension, and normalization. Opening an old catalog with a different descriptor fails with `ErrStoreMismatch`. A model change uses an explicit new catalog and vector pool generation. Clyde publishes that generation only after it is searchable, while the prior generation remains readable. Clyde does not automatically remove referenced vectors or occurrences from either generation.

## Proposed configuration contract

The following keys are the proposed `[conversation.semantic]` contract. An omitted library budget uses the library's stated default. Changes to these keys use `RouteReload`. A model, revision, dimension, normalization, analyzer, catalog path, or vector pool change creates a separately configured generation. Clyde builds and verifies the new generation before publishing it. Opening an existing catalog with a mismatched descriptor returns `ErrStoreMismatch`; the prior generation remains readable.

| Keys | Type and default | Library mapping or Clyde behavior |
| --- | --- | --- |
| `ingestion_enabled`, `search_enabled` | Existing booleans, false unless configured. | Independent write and read switches. |
| `collection_id`, `indexed_content` | Existing string and selector list. The current selector default remains chat plus tool calls. | Map collection ID to namespace and selectors to Clyde projection. |
| `projection_profile` | Explicit `p1`, `p2` or `p3` when embedded search or ingestion is enabled. No default. | `p3` records original source text and prepared byte spans and is required for ingestion. `p1` and `p2` permit search-only access with unavailable context and absent source identity. |
| `indexed_providers`, `indexed_roles` | String lists. Empty means every supported provider and role. | Clyde content admission and generic scalar predicates. |
| `include_archived`, `include_subagents` | Booleans, false. | Clyde content admission and query predicates; metadata refresh still runs for already indexed owners. |
| `catalog_path`, `lock_path`, `pool_id` | Explicit paths and pool ID when enabled. | `StoreDescriptor.CatalogPath`, `LockPath`, `PoolID`. Existing configured values are never silently repurposed. |
| `milvus_address`, `milvus_database`, `milvus_collection` | Explicit endpoint and names for the Milvus profile. | Clyde creates the SDK client and injects `library/milvus`; the library does not close the client. |
| `embedding_base_url`, `embedding_api_key_env`, `embedding_api_key_file` | Explicit OpenAI-compatible endpoint and an optional credential reference. Reject simultaneous environment and file references. | Clyde resolves any configured credential and supplies the library embedding adapter. Support local endpoints without authentication. Never log the credential. |
| `embedding_request_timeout`, `embedding_max_attempts`, `embedding_backoff_base` | Explicit request timeout; defaults 4 attempts and 200 milliseconds for retry settings. Zero timeout uses the caller deadline. | Map to the exported embedding adapter configuration. Reject negative timeouts, nonpositive attempt counts, and negative retry delays. |
| `embedding_model`, `embedding_revision`, `vector_dimension`, `normalization`, `analyzer_identity`, `query_instruction_prefix` | Explicit model identity, resolved revision, positive dimension, normalization identifier, analyzer identity, and optional prefix. | `StoreDescriptor` and `library.Config`. A descriptor mismatch fails before writes. |
| `max_batch_rows`, `max_batch_bytes` | Positive integers; defaults 256 and 8 MiB. | `library.Config.MaxBatchRows` and `MaxBatchBytes`. |
| `raw_batch_target_bytes` | Positive integer; default 8 MiB. | Clyde source-loading admission target. Load an oversized artifact alone and measure its peak memory separately. This does not change the library write batch limit. |
| `query_block_size`, `query_workers`, `max_temporary_bytes`, `max_snapshot_bytes`, `snapshot_ttl`, `query_timeout` | Positive budgets; defaults 512, 2, 1 GiB, 256 MiB, 10 minutes, and 30 seconds. | Same named `library.Config` fields. Exhaustion returns a typed failure, never a short page. |
| `max_page_size`, `max_query_bytes`, `max_filter_depth`, `max_filter_values` | Nonnegative integers; default zero disables the individual request limit. | Same named `library.Config` fields. Reject an oversized request with `ErrInvalidRequest`; never truncate it. |
| `bm25_k1`, `bm25_b`, `rrf_k` | Finite numbers; defaults 1.2, 0.75, and 60. | Same named `library.Config` fields. Query settings enter the cursor identity. |

The global `conversation.include_subagent_conversations` setting currently controls raw index visibility. Clyde makes semantic subagent admission independent of ordinary list visibility while continuing to use the registered provider readers. Unknown selectors, missing enabled store fields, invalid numeric budgets, and model descriptor mismatches fail configuration or opening before search accepts requests. Remove the obsolete RPC client and its backend and socket settings.

The search snapshot expires after ten minutes of inactivity by default. Every successful next-page request renews its saved expiration. Active paging can continue beyond ten minutes without changing the saved order. An expired session returns the expiration error.

## Error contract

| Library result | Clyde CLI and MCP result | gRPC status |
| --- | --- | --- |
| `ErrInvalidRequest`, `ErrCursorMismatch` | `conversation_search_source_refused` with the safe reason. | `InvalidArgument` |
| `ErrCursorExpired` | `conversation_search_source_refused` with a restart paging reason. | `FailedPrecondition` |
| `ErrStoreMismatch` | Opening the mismatched store fails. Any prior valid generation remains readable. | `FailedPrecondition` |
| `ErrAppendConflict`, `ErrStaleGeneration` | The ingestion operation fails. Freshness reports pending work or the error; search continues on prior committed data. | `FailedPrecondition` |
| `ErrVectorMissing`, `ErrVectorCorrupt` | `conversation_search_source_failed`; never return a partial page. | `Internal` |
| `ErrDeadline` | `conversation_search_source_failed` with a deadline reason. | `DeadlineExceeded` |
| `ErrResourceLimit` | `conversation_search_source_refused` with a resource reason. | `ResourceExhausted` |
| Disabled search switch | Existing `conversation_search_disabled`. | `FailedPrecondition` |

Unexpected library errors become `conversation_search_source_failed` and `Internal`. Clyde logs the cause without transcript text. An offset request consumes a cursor chain inside one library snapshot; the public result retains `offset`, `next_offset`, and `has_more`. A later independent offset request opens a new snapshot and can see newly committed rows. The search API adds optional request `cursor`, response `next_cursor`, and per-match `context_state` fields to the daemon protobuf, domain types, CLI JSON, and MCP result. The CLI accepts `--cursor`; the MCP operation accepts the same optional value. Old clients can ignore the new fields. A cursor continues under the same query, filter, ranking settings, and snapshot; expiry or mismatch returns the typed error above.

The CLI accepts `--conversation-ids` as a repeated or comma-separated membership filter. `--conversation-ids=` selects no conversations. MCP accepts `conversation_ids` as an optional string array; an empty array selects no conversations. An omitted or null array applies no membership restriction. A positional conversation ID intersects the explicit membership set. `--per-conversation-limit` and MCP `per_conversation_limit` cap each conversation after ranking; zero is uncapped. `--include-subagents` and MCP `include_subagents` include stored subagent occurrences. Queries exclude subagents by default even when ingestion selects them.

## Prove the behavior

CLI and MCP results must use the same ordered conversation IDs, message indexes, scores, excerpts, and context state. A visible match ranked below excluded matches must appear. Repeated queries and different page sizes must preserve order. Filtered and unfiltered pages must report exact continuation. Errors must remain errors.

Each p3 hit adds an optional `source_identity` object with provider conversation ID, original message index, content kind, tool index, and half-open `source_byte_start`/`source_byte_end`. The values identify selected source content independently of storage row keys and truncated snippets. CLI, MCP and daemon responses preserve the same identity. Legacy hits omit the object.

An isolated real Milvus and SQLite test covers first ingestion, duplicate content, appended messages, metadata-only updates, truncated artifacts, source loss, policy change, interrupted delivery, restart, and unchanged replay. The unchanged second pass must perform zero embeddings and zero vector writes. Record source messages, selected nonempty rows, sent rows, new distinct embeddings, reused vectors, and retained occurrences separately. A clean install report measures source reading, projection, embedding, persistence, searchable completion, model startup, throughput, disk, memory, and filtered and unfiltered latency. Estimate full corpus work from selected eligible content, not historical Milvus row counts. Coverage or production latency failure blocks release. No fixed depth limit may silently truncate a page.

A one-time reset of the current production corpus requires a later measured migration decision. This design performs no reset, production deployment, or deletion.
